# Validation checks are byte-length, null-conformance, and sampling; drift checks are task-scoped and closed by the operator

`CONTEXT.md` named five 校验项 (validation check) values, but three of them — 大记录值完整性 (large record value integrity), 非空约束符合性 (null constraint conformance), 抽样值比对 — had no comparison, no reason codes, and no applicability rule, and ADR-0024 required drift checks without saying where their results live. Resolved in [#94](https://github.com/liumingjian/dbx/issues/94).

- **大记录值完整性 compares source-byte length, not content.** It applies only to a 大记录表 (large record table), and within it only to the columns whose value or row exceeded the 1 MiB boundary. Source and target each compute non-null count, `SUM`, and `MAX` of the source-byte length expression ADR-0003 already fixes for preflight, `COALESCE(OCTET_LENGTH(CAST(E AS BINARY)), 0)`, batched alongside the §9.2 exact-numeric aggregates so it costs no extra scan. It covers every row rather than a sample, and proves length equality only: results state that coverage and never imply value equality. A difference is `FAIL / LARGE_VALUE_LENGTH_MISMATCH`; a changed final source count is `INCONCLUSIVE / SOURCE_CHANGED`; a column whose byte length the pair cannot prove comparable across engines is `NOT_APPLICABLE / BYTE_LENGTH_NOT_COMPARABLE`; a table that is not a large record table is `NOT_APPLICABLE`.
- **Byte-length comparability is a pair capability, never an assumption.** MySQL's `CAST(E AS BINARY)` yields bytes in the column's source character set and PostgreSQL's `octet_length` yields UTF-8 bytes, so the two agree for binary and BLOB columns and for UTF-8 text, and disagree for a `latin1` text column. `dialect` decides per column; `validation` marks what it cannot prove `NOT_APPLICABLE` rather than comparing anyway.
- **A large record table is never value-sampled.** §9.3's default target of 1000 rows against rows of up to 20 MiB would move 20 GiB. 抽样值比对 records `NOT_APPLICABLE / LARGE_RECORD_TABLE`, and 大记录值完整性 is the check that covers those tables.
- **非空约束符合性 covers every source `NOT NULL` contract column, not only primary-key components.** It is a null count per column on each side, folded into the existing at-most-300-column aggregate batches. Its purpose is not a violated target constraint — that row fails at write time and the database enforces it — but a NULL *manufactured by conversion*, where the target contract relaxed the constraint and an approved zero-date or out-of-range conversion landed NULL. Source count zero with a non-zero target count is `FAIL / UNEXPECTED_NULL_IN_TARGET`; a non-zero source count is `INCONCLUSIVE / SOURCE_CHANGED`, because the source contradicts its own contract. Primary-key components keep their own `FAIL / NULL_PRIMARY_KEY_COMPONENT`, which additionally denies row identity.
- **抽样值比对 is technical plan §9.3's manual deterministic sampling, and no checksum is involved.** The `CONTEXT.md` English name Value checksum sample was wrong and becomes **Value sample**; the Chinese 抽样值比对 is unchanged and never said otherwise. A cross-engine checksum would require both engines to produce byte-identical canonical representations, which §9.2 already refused when it marked string and collated extrema not applicable rather than manufacture a cross-database order: trailing `CHAR` spaces, `jsonb` key order, and float text would each become a false `FAIL`, and a DBA has no way to tell a false one from a real one.
- **漂移检查 (drift check) is a task-scoped immutable record.** It belongs to no run: a pre-run check happens before its run exists, and the closing check follows the last run. It is recorded on the 迁移任务 (migration task), owned by `workflow`, carries its occasion (运行前 or 收口) and one item per already-migrated table, and reuses the 校验项 state and reason vocabulary — `INCONCLUSIVE / SOURCE_CHANGED`, or ADR-0024's "no drift observed", never a pass. `orchestration` executes `validation`'s `driftPlan` and writes the facts in. 整库结论 (task conclusion) reads the latest closing check.
- **The operator marks the last run, by closing the task.** DBX prompts that 收口 is available once every in-scope table holds a terminal result, and never performs it: ADR-0024 already refuses to make the freeze decision for the operator, and no automatic rule can tell a table the operator means to abandon from one they mean to re-migrate. Closing runs the closing drift check, produces the task conclusion, and only then may the 整库冻结承诺 (task write freeze) be released. Closing is not terminal: a drifted table stays a 重新迁移 (re-migration) candidate, any run after a closing check requires a new one, and the task conclusion always reads the latest.

## Considered options

- **Dropping 大记录值完整性 from v1** and admitting that large record values are covered only by "the write succeeded". Rejected: large record values are exactly the data the other checks cannot reach, and a full-table length comparison is one aggregate away.
- **Content comparison or a hash for large record values.** Rejected for the reason the checksum option is rejected below, and because it would move the whole table across the wire a second time.
- **非空约束符合性 as primary-key components only** (technical plan §9.2 as written). Rejected: it leaves conversion-manufactured NULLs in ordinary columns uncovered while the wider check rides along in a scan already being paid for.
- **A cross-engine value checksum,** as `CONTEXT.md`'s English name suggested. Rejected: normalization differences make it produce failures that are not differences, and it cannot be shown to a DBA as evidence of anything.
- **Recording drift results as a 校验执行 (validation execution) on a run.** Rejected: a validation execution is a run's retained result after 写入完成 (write complete), and neither drift check has a run to belong to.
- **Automatic closing once every table reaches a terminal result.** Rejected: it decides the end of a person's freeze commitment for them, and mistakes an abandoned table for a finished one.

## Consequences

`validation`'s plan gains two check kinds that ride in the existing aggregate batches, and `dialect` gains a per-column byte-length-comparability capability for the pair. Large record tables are covered by length rather than by value, which the report must say. `workflow` gains 漂移检查 as a task-scoped record and `orchestration` a closing step; the task detail page gains a 收口 action and the prompt that precedes it. `CONTEXT.md` renames one English term and adds one.
