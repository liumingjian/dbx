# Slices are module-horizontal, and a cross-module shape belongs to the sub-spec

`docs/spec/README.md` §How to use it makes the slice unit a group of obligations inside one module, and ADR-0018 §Session rule makes one session change one module. Nothing recorded that as a choice. The string "vertical slice" appears nowhere in the corpus, and `mattpocock-skills:to-tickets` — the skill that drafts every implementation ticket — requires the opposite in its `<vertical-slice-rules>`: "Each slice cuts a narrow but COMPLETE path through every layer (schema, API, UI, tests): vertical, NOT a horizontal slice of one layer." Nine sub-specs were sliced against a convention that had never been weighed against the default it contradicts, so an agent arriving with that default reads the convention as an accident. Resolved in [#154](https://github.com/liumingjian/dbx/issues/154).

- **A slice is module-horizontal, and this is a deliberate override of the vertical-slice default, not an oversight.** A slice is a group of obligations inside one sub-spec, proved at the ladder rung its §Verification section names (ADR-0022). The override is recorded here so it is arguable: a later session that wants vertical slices argues with this ADR instead of discovering the convention and assuming nobody weighed it.

- **What the override buys.** One session holds one module's whole context — its sub-spec, its contract test, the `api` of what it consumes — which is the constraint ADR-0018 exists to serve and the third judgement criterion the map states ("对 agent 好"). It also keeps the cross-module slice graph acyclic and the frontier computable: every blocking edge points at an earlier module in §Where to start's order, so what is takeable now is a query rather than a planning exercise. Vertical slices make the unit wider than one module and strand that machinery.

- **What the override costs, accepted knowingly.** A module's slice 1 carries no behaviour — `dialect`'s is an "api skeleton", `connection`'s the six entry-point signatures "with no byte yet encrypted". Finishing every slice of a module leaves the DBA able to do nothing new; user-observable value arrives only when `orchestration` reaches down. A leaf module lands ahead of every consumer, so no compiling caller contradicts its `api` until later. These are real and they are the price of the paragraph above; they are not evidence that the convention was never chosen.

- **A sub-spec adjudicates every shape that crosses a module boundary.** A sub-spec may not delegate such a shape to a slice, a contract test, or §Implementer decides. §Implementer decides holds module-internal choices only — a nonce policy, a fingerprint algorithm, a retry count — never a type another module names. This is what makes the accepted cost above survivable: when no consumer can yet contradict an `api`, the sub-spec is the only thing that can, so it must actually rule rather than defer. `docs/spec/connection.md` §Interface was the corpus's one violation ("Parameter shapes are fixed by slice 1's `ConnectionContractTest`") and is fixed with this ADR.

- **An ArchUnit rule that merely transcribes a sub-spec obligation changes together with that obligation, and the sub-spec amendment is the record.** ADR-0018 §Enforcement's "changing a rule is an architectural decision recorded in an ADR" governs rules that state an architectural constraint — dependency direction, `api`-only access, purity. It over-charges a rule that only restates what a sub-spec already says, such as `ConnectionBoundaryTest`'s check that `connection.api` declares exactly six entry points: that rule's authority is obligation 6, not itself. Amending it means amending the obligation first, in the module's own session, and no new ADR. Without this carve-out the correction channel for a frozen-early `api` looks like it costs an ADR, which is exactly the pressure that makes an agent treat a transcribed rule as unopenable.

- **ADR-0018's session rule stands, but on module context rather than on a token count.** ADR-0018 opens "DBX is built entirely by agents working in 100K-token sessions" and derives the session rule from that figure. The figure has expired — `connection` was implemented in a 1M-token session — so the derivation is replaced: one session changes one module because one module is the unit whose obligations, contract test and consumed `api` can be held and reasoned about at once, at any context size. A bigger window buys a session more room inside its module; it does not make the whole repository a sound working surface.

## Considered options

- **Rule vertical slices and drop the session rule**, on the grounds that `to-tickets` states a general design convention and a project convention contradicting one should lose. Rejected. A general default is a starting point to argue from, not a precedence rule that outranks a recorded decision — `to-tickets` itself carves out wide refactors, so it concedes that context decides. The cost is the decisive part: the 16 sub-specs map one-to-one onto modules, each owning its own blocking edges, and a leaf such as `connection` has no user-observable surface, so a tracer bullet through credential crypto necessarily also cuts `orchestration` and `web`. That recuts a 114-slice graph that is working, to reach a destination — a handoff-ready v1 plan — that the recut does not advance. The scoping offered for it ("already-merged slicing is not reopened") does not hold either: only `connection` slice 1 is on `main`, slices 2–4 are in open PR [#153](https://github.com/liumingjian/dbx/pull/153).

- **Keep module-horizontal slicing and add a consumer-first obligation** — a module's last slice must land one real consumer call site, or the `api` freeze waits until the first consumer compiles. Rejected. It aims at a cost the evidence does not support: `connection`'s six entry points were not a slice-1 guess but a transcription of ADR-0036's Interface column into the sub-spec's obligation 6. The part that was a guess was the parameter shapes, and that was a spec delegation, addressed above at its source. A consumer-first rule would also make a leaf module's completion wait on a module several places later in the build order, reintroducing the ordering problem the convention solves.

- **A hybrid**: module slices for pure and leaf modules, vertical slices where the outcome is user-observable. Rejected: "user-observable outcome" is a soft test that every ticket would relitigate, and `orchestration` — where it would bite — is exactly where module-horizontal slicing already reaches down through the `api` of everything below it.

- **Define 切片 (slice) in `CONTEXT.md`.** Rejected: `CONTEXT.md` is the DBA's domain vocabulary and ADR-0018 §Module context keeps implementation names out of it. A slice is the vocabulary of the people building the platform. The definition stays in `docs/spec/README.md` §How to use it, where a session drafting or implementing a ticket already reads, and this ADR holds the rationale (ADR-0030 for the same distinction on the operator's side).

- **Enforce "a sub-spec adjudicates cross-module shapes" with a script.** Rejected: a check that greps sub-specs for delegating phrasing is a keyword blacklist, evaded by rewording, and worse than nothing because it looks like a gate. The shape of a type cannot be asserted by ArchUnit, which sees dependency direction only. This rule is a judgement made when editing a sub-spec, like the `CONTEXT.md` length cap ADR-0018 §Module context deliberately stopped asserting.

## Consequences

`docs/spec/README.md` §How to use it states that a slice is module-horizontal and names the overridden default, so a ticket-drafting session meets the ruling where it already reads rather than having to reach an ADR. It also carries the cross-module shape rule, for the same reason.

ADR-0018's opening paragraph no longer rests the session rule on 100K tokens, and §Enforcement distinguishes an architectural rule from a transcribed one. No ArchUnit rule, module boundary, ownership row or sub-spec §Slices section changes; `dialect`'s and `connection`'s landed slices are untouched.

`docs/spec/connection.md` §Interface adjudicates the parameter shapes it had delegated. It ratifies what PR [#153](https://github.com/liumingjian/dbx/pull/153) already built — every entry point names `connection`-owned types, and `BackupId` is an opaque identity the module never interprets — so the alignment costs that PR no change. The corpus has no other delegation of this kind.
